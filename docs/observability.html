可观测性

可观测性是三个独立策略轴之一（ObservabilityType.NONE / BASIC / FULL）。 FtpPool 提供四条观测通道：编程式统计、Micrometer 指标、JMX、结构化日志。

1. 编程式统计 FtpPoolStats

FtpPoolStats s = pool.stats();
int total   = s.total();               // 总连接数（空闲 + 借出）
int active  = s.active();              // 当前借出
int idle    = s.idle();                // 当前空闲
int pending = s.pending();             // 正在等待连接的 borrower 数
long created = s.created();
long destroyed = s.destroyed();
long borrowed = s.borrowed();
long returned = s.returned();
long borrowTimeouts = s.borrowTimeouts();
long validationFailures = s.validationFailures();

统计快照轻量、无副作用，可安全地在健康检查或自定义监控线程中调用。

2. Micrometer 指标

需要 ftp-pool-micrometer。Spring Boot 下存在 MeterRegistry Bean 时自动接入。

池级指标

指标名类型来源
ftp.pool.sizeGaugestats.total()
ftp.pool.activeGaugestats.active()
ftp.pool.idleGaugestats.idle()
ftp.pool.pendingGaugestats.pending()
ftp.pool.borrowCounter累计借出
ftp.pool.borrow.timeoutCounter借出超时
ftp.pool.createCounter累计创建
ftp.pool.destroyCounter累计销毁
ftp.pool.validation.failureCounter校验失败

操作级指标

指标名类型标签
ftp.operation.<op>Counterresult=success|failure
ftp.operation.latencyTimeroperation=<op>
ftp.operation.bytesCounteroperation=<op>（仅传输类操作）
ftp.operation.slowCounter超过慢操作阈值的次数

<op> 取值来自 FtpOperation（小写），如 borrow、execute、upload、download、delete、list、 rename、make_directory、change_directory、connect、login、 validate、reset、return、complete_pending。

无高基数标签：用户名、文件路径、完整 FTP 命令永远不会成为指标标签。 默认标签只有 pool（以及 Spring Boot 场景下的 host / port / protocol）。

3. JMX

需要 ftp-pool-jmx。编程式构建时默认自动注册；Spring Boot 下由 spring.tidepool.ftp.observability.jmx 控制。

对象名：

com.ftppool:type=FtpPool,name=<poolName>

只读属性

属性含义
PoolName池名
Total / Active / Idle / Pending实时连接数
BorrowCount / ReturnCount累计借出 / 归还
BorrowTimeoutCount累计借出超时
CreateCount / DestroyCount累计创建 / 销毁
ValidationFailureCount累计校验失败

操作

操作作用
clearIdle()销毁所有空闲连接
validateAll()校验所有空闲连接，销毁无效的
shutdown()关闭整个池

JMX 属性均为廉价的只读快照，不暴露任何凭据或高基数数据。

4. 结构化日志

LoggingFilter 在生命周期转换时输出带上下文的日志行，字段包括： pool、connectionId、operation、duration、result、exceptionType。

[execute:done] pool=main, connectionId=ftp-000012, operation=EXECUTE, duration=42ms, result=success
[op:error] operation=UPLOAD, exceptionType=CONNECTION, error=... 
[borrow:done] pool=main, connectionId=ftp-000012, ...
  • LoggingFilter() 默认只记录关键转换（execute 完成、错误）；LoggingFilter(true) 打开详细 debug 级别。
  • 密码永不入日志：日志上下文根本不会携带凭据。

5. 慢操作与连接泄漏

慢操作

操作耗时超过 slowOperationThreshold（默认 3s）时，SlowOperationFilter 输出：

Slow operation: pool=main, connectionId=ftp-000012, operation=DOWNLOAD, duration=8123ms

同时累加 ftp.operation.slow 计数。

连接泄漏检测

连接借出超过 leakDetectionThreshold（默认 30s）未归还，泄漏检测器会告警并打印借出线程与调用栈：

Possible connection leak: pool=main, connectionId=ftp-000012, borrowed by thread=..., stack=...

检测只告警，不强制销毁。设为 0 或负值可禁用。典型原因是业务代码忘记 release，或没有用 execute() 包住借还。

6. 扩展过滤链

可观测性由 FtpFilter SPI 驱动。自定义过滤器通过 FtpPoolBuilder.addFilter(...) 加入， 或实现 FtpFilterProvider 并注册到 META-INF/services。

pool = FtpPoolBuilder.builder()
        .host("ftp.example.com")
        .addFilter(new MyAuditFilter())
        .build();

追踪（OpenTelemetry / Micrometer Tracing）可通过 FtpTracer / TracingFilter SPI 接入。
