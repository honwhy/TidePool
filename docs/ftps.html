FTPS 指南

FTPS = FTP over TLS。上层 API 与明文 FTP 完全一致，只是 protocol 与 TLS 配置不同。 适配器在底层创建对应的 FTPSClient，用户不会接触任何 Apache Commons Net 类型。

1. 选择协议

FtpProtocol默认端口说明
FTP21明文 FTP
FTPS_EXPLICIT21控制通道先明文连接，再 AUTH TLS 升级；最常用
FTPS_IMPLICIT990连接即 TLS，无需协商

port=0（或不设置）时使用协议默认端口。

2. 最小配置（Explicit，推荐）

import io.ftppool.api.FtpProtocol;
import io.ftppool.core.FtpPoolProfiles;
import io.ftppool.core.FtpSslConfig;

FtpPool pool = FtpPoolProfiles.hybrid()
        .host("ftps.example.com")
        .protocol(FtpProtocol.FTPS_EXPLICIT)
        .sslConnection(FtpSslConfig.secureDefaults())   // 企业证书链 → JVM 默认信任库
        .username("user")
        .password(System.getenv("FTP_PASSWORD"))
        .build();

FtpSslConfig.secureDefaults() 的含义：使用 JVM 默认信任库、开启 hostname 校验、不信任任意证书。

3. TLS 配置模型

public record FtpSslConfig(
        SSLContext sslContext,      // 显式上下文，优先级最高
        TrustManager[] trustManagers,
        KeyManager[] keyManagers,   // 客户端证书（双向 TLS）
        boolean trustAll,           // UNSAFE
        boolean hostnameVerification)

构建安全上下文时的优先级：

显式 sslContext
   ↓ 未提供
trustManagers / keyManagers 组装新的 TLS context
   ↓ 未提供
JVM 默认上下文（默认信任库）

自定义信任链 / 客户端证书（双向 TLS）

SSLContext ctx = SSLContext.getInstance("TLS");
ctx.init(keyManagers, trustManagers, null);

FtpSslConfig config = new FtpSslConfig(ctx, null, null, false, true);
// 或流式：FtpSslConfig.secureDefaults().withSslContext(ctx)

FtpSslConfig 只使用 JDK 的 javax.net.ssl.* 类型，因此 ftp-pool-core 仍保持无第三方依赖。

4. 安全底线（不可谈判）

TLS 校验不允许默认关闭。唯一能跳过校验的方式是显式命名的 FtpSslConfig.insecureTrustAll()， 它会同时跳过证书校验与 hostname 校验，仅限本地开发与测试服务器。

// UNSAFE —— 开发/测试专用
.sslConnection(FtpSslConfig.insecureTrustAll())

适配器应用 trust-all 时会打印醒目告警：

FTPS trust-all enabled — server certificate AND hostname verification disabled. DEVELOPMENT ONLY.

生产环境永远使用 secureDefaults() 或其派生的自定义信任配置。

5. Spring Boot 配置

spring:
  tidepool:
    ftp:
      protocol: ftps-explicit         # ftp | ftps-explicit | ftps-implicit
      host: ftps.example.com
      port: 21
      username: user
      password: ${FTP_PASSWORD}
      ssl:
        trust-all: false              # UNSAFE，开发/测试专用
        hostname-verification: true

若容器中存在自定义 SSLContext Bean，自动配置会将其注入 FtpSslConfig（优先级最高）。 设置 spring.tidepool.ftp.ssl.trust-all=true 会覆盖它并打印 UNSAFE 告警。

6. FTPS 特有行为

  • 数据通道保护：适配器对 FTPS 强制要求受保护的数据信道（Data Channel Protection）， 未满足视为 broken 连接并销毁，而不是回池。
  • 建连顺序：connect → TLS 协商 → login → BINARY → passive → 数据保护 → 记录初始目录； 任一步失败即销毁并抛出分类后的 FtpException（CONNECTION / AUTHENTICATION 等）。
  • 已端到端验证：Explicit 与 Implicit FTPS 均通过内嵌 Apache MINA FTPS 服务器的集成测试。

7. 排查清单

现象检查
证书验证失败服务器证书是否被 JVM 信任库信任；若是公司 / 私有 CA，配置自定义 trustManagers。
hostname 不匹配确认服务器证书的 CN/SAN 与 host 一致。这是预期失败，不要用 trust-all 绕过。
双向 TLS 失败是否配置了 keyManagers（客户端证书与私钥）。
连上后传输失败数据连接保护是否开启；防火墙是否放行被动模式的数据端口（PASV）。
对接测试服务器临时使用 insecureTrustAll()，且只限本地环境；上线前务必换回安全配置。

更多连接类问题见 排错建议。
