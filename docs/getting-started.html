快速开始

目标：从零跑通「引入依赖 → 构建 Pool → 上传/下载文件」。假定环境为 Java 17+ 与 Maven 或 Gradle。

1. 环境要求

项要求
JDK17 或更高（项目编译目标 maven.compiler.release=17）
构建工具Maven 3.8+ 或 Gradle 7+
Spring Boot（可选）3.x（使用 starter 时）
FTP 服务端任意标准 FTP/FTPS 服务器（vsftpd、IIS、FileZilla Server、Apache MINA FtpServer 等）

2. 引入依赖

FtpPool 采用「核心 + SPI 实现」分层：ftp-pool-core 不直接依赖任何引擎或 FTP 客户端， 运行时通过 META-INF/services 发现实现。因此必须把引擎模块和适配器模块放到 classpath，否则构建 Pool 时会抛异常。

最小依赖集（Fast 引擎）

<properties>
    <ftp-pool.version>0.1.0-SNAPSHOT</ftp-pool.version>
</properties>

<dependencies>
    <!-- 核心：FtpPool / FtpPoolBuilder / FtpClientTemplate -->
    <dependency>
        <groupId>io.ftppool</groupId>
        <artifactId>ftp-pool-core</artifactId>
        <version>${ftp-pool.version}</version>
    </dependency>

    <!-- 高性能引擎（默认 FAST）-->
    <dependency>
        <groupId>io.ftppool</groupId>
        <artifactId>ftp-pool-engine-fast</artifactId>
        <version>${ftp-pool.version}</version>
    </dependency>

    <!-- Apache Commons Net 适配器：FTP / FTPS -->
    <dependency>
        <groupId>io.ftppool</groupId>
        <artifactId>ftp-pool-adapter</artifactId>
        <version>${ftp-pool.version}</version>
    </dependency>
</dependencies>

Gradle 等价写法：

def ftpPoolVersion = "0.1.0-SNAPSHOT"

dependencies {
    implementation "io.ftppool:ftp-pool-core:$ftpPoolVersion"
    implementation "io.ftppool:ftp-pool-engine-fast:$ftpPoolVersion"
    implementation "io.ftppool:ftp-pool-adapter:$ftpPoolVersion"
}

ftp-pool-core 会传递引入 ftp-pool-api（FtpPool / FtpConnection 等公共类型），无需单独声明。

按需追加的模块

artifact何时需要
ftp-pool-engine-commons使用 commons() profile 或 engine=COMMONS
ftp-pool-observability需要指标 / 慢操作 / 审计日志过滤链（hybrid()/monitor() 会用到）
ftp-pool-micrometer对接 Micrometer（Prometheus 等）
ftp-pool-jmx注册 JMX MBean
ftp-pool-spring-boot-starterSpring Boot 应用一键接入（已含 adapter + engine-fast + observability + micrometer + jmx）

生产推荐 hybrid()，请在上面的最小集之外再加 ftp-pool-observability（按需再加 ftp-pool-micrometer / ftp-pool-jmx）。 缺少 ftp-pool-observability 时不会报错，但会打印 No FtpFilterProvider ... on the classpath 警告且没有任何指标。 上面的最小依赖集只够支撑 fast() 这类 observability=NONE 的用法。

3. 第一个程序

import io.ftppool.api.FtpPool;
import io.ftppool.core.FtpPoolProfiles;

import java.io.InputStream;

public class Demo {
    public static void main(String[] args) throws Exception {
        FtpPool pool = FtpPoolProfiles.hybrid()          // 默认推荐
                .host("ftp.example.com")
                .port(21)
                .username("user")
                .password(System.getenv("FTP_PASSWORD")) // 从环境变量读取，勿硬编码
                .poolName("main")
                .build();

        try (pool) {                                     // FtpPool 实现 AutoCloseable
            try (InputStream in = Demo.class.getResourceAsStream("/report.csv")) {
                boolean ok = pool.execute(ftp ->
                        ftp.upload("/upload/report.csv", in));
                System.out.println("uploaded=" + ok);
            }
        }
    }
}

也可以显式手动借还，适合需要精细控制生命周期的场景：

FtpConnection conn = pool.borrow();                 // 或 pool.borrow(Duration.ofSeconds(2))
try {
    FtpFile[] files = conn.listFiles("/data");
    // ... 业务逻辑 ...
} finally {
    pool.release(conn);                             // 必须归还，否则连接泄漏
}

4. 常用操作

在 pool.execute(callback) 中拿到 FtpConnection 后，可调用以下方法：

操作方法说明
上传boolean upload(String path, InputStream in)STOR，返回是否成功
下载boolean download(String path, OutputStream out)RETR
删除boolean delete(String path)DELE
重命名 / 移动boolean rename(String from, String to)RNFR/RNTO
创建目录boolean makeDirectory(String path)MKD
列目录FtpFile[] listFiles(String path)返回与 Commons Net 解耦的 FtpFile 记录
切换目录void changeDirectory(String path)CWD，归还时自动重置
当前目录String currentDirectory()PWD
流式读取InputStream retrieveFileStream(String path)需自行调用 completePendingCommand()
流式写入OutputStream storeFileStream(String path)需自行调用 completePendingCommand()
 
FtpFile[] files = pool.execute(ftp -> ftp.listFiles("/data"));
for (FtpFile f : files) {
    System.out.printf("%s  %d bytes  dir=%s%n", f.name(), f.size(), f.directory());
}

pool.execute(ftp -> ftp.rename("/data/a.txt", "/data/archive/a.txt"));
pool.execute(ftp -> ftp.makeDirectory("/data/archive"));

rename / makeDirectory 在接口上带默认实现（抛 UnsupportedOperationException）， 当前 Apache Commons Net 适配器已支持；若接入自定义后端可能不支持。

5. FtpClientTemplate（更薄的门面）

FtpClientTemplate 是 FtpPool 之上的轻封装，常用操作一行调用，Spring Boot 下由 starter 自动注册为 Bean。

FtpClientTemplate ftp = new FtpClientTemplate(pool);

ftp.upload("/data/report.csv", input);       // 返回 boolean
ftp.download("/data/report.csv", output);    // 返回 boolean
ftp.delete("/data/report.csv");              // 返回 boolean
boolean ok = ftp.execute(c -> c.rename("/a.txt", "/b.txt"));
FtpPoolStats stats = ftp.stats();

6. 连接状态会自动重置

FTP 连接是有状态的（工作目录、文件类型、被动模式、编码、传输状态）。归还时会自动重置为： BINARY 文件类型、passive 模式、初始工作目录、UTF-8 编码。

  • 重置成功 → 回到空闲队列，可再次借出；
  • 重置失败 → 标记为 broken 并销毁，绝不放回池中。

所以你可以在业务里放心 changeDirectory、切文件类型，归还时会被清理干净。

7. 关闭

pool.close();   // 停止借出 → 等待在途操作（shutdown-timeout）→ 关闭空闲 → 关闭活跃 → 停止后台维护

close() 幂等；Spring 容器关闭时会自动调用。shutdownTimeout 默认 10s，设为 0 表示不等待在途操作。
