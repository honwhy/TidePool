配置参数

配置分三层，互不混淆：

层承载类型内容
连接参数FtpConnectionSettingshost / port / username / password / protocol / encoding / ssl
池参数PoolConfiguration大小、超时、回收、校验、泄漏检测等池机制
策略轴PoolEngineType / LifecycleType / ObservabilityType引擎、生命周期、可观测性

连接参数

通过 FtpPoolBuilder（或 Spring Boot 的 spring.tidepool.ftp.*）设置。所有参数在 build() 时汇总为不可变记录 FtpConnectionSettings。

参数Builder 方法默认值说明
host host(String) 必填 FTP 服务器主机名或 IP。build() 时为空会抛 NullPointerException。
port port(int) 0 → 协议默认 FTP / FTPS-explicit 默认 21，FTPS-implicit 默认 990。显式传 0 或负值即用协议默认端口。
username username(String) anonymous 为 null 时按匿名登录处理。
password password(String) "" 为 null 时按空密码处理。密码绝不出现在日志、指标、JMX 或异常消息中；FtpConnectionSettings.toString() 会将其掩码为 ******。
protocol protocol(FtpProtocol) FTP FTP / FTPS_EXPLICIT / FTPS_IMPLICIT，决定适配器创建哪种物理客户端。
encoding encoding(String) UTF-8 控制通道编码。为 null 或空白时回落 UTF-8。
ssl sslConnection(FtpSslConfig) FtpSslConfig.secureDefaults() FTPS 的 TLS 策略。默认使用 JVM 信任库并开启 hostname 校验。详见 FTPS 指南。

池参数

通过 FtpPoolBuilder 或 Spring Boot 的 spring.tidepool.ftp.pool.* 设置。下表中的「0 / 负值」语义已按实现标注。

参数默认值说明 / 0 与负值语义
poolNamedefault日志、指标、JMX 中的池标识；空或空白时回落 default。
minIdle2最低空闲连接数，后台回填目标。负值回落默认。必须 ≤ maxSize，否则 IllegalArgumentException。
maxSize20池上限（含借出 + 空闲）。≤ 0 回落默认。
connectionTimeout3sborrow 等待超时，超时抛 FtpPoolException(POOL_TIMEOUT)。非正值回落默认。
socketTimeout30s控制连接 socket 读超时。非正值回落默认。
dataTimeout60s数据连接（传输）超时。非正值回落默认。
idleTimeout5m空闲超过该时长即被后台驱逐。0 或负值 = 禁用空闲驱逐。
maxLifetime30m连接最大寿命，到期在归还/后台回收时销毁，防 NAT / 防火墙静默断连。必须为正，不可禁用。
validationInterval30s借出前的校验节流周期：仅当连接空闲超过该间隔才做一次 NOOP；后台 housekeeper 周期同样取该值（最小 1s）。0 或负值 = 不做借出前校验。
maxCreateConcurrency2并发建连节流，防止连接风暴 / 认证风暴压垮服务器。≤ 0 回落默认。
leakDetectionThreshold30s连接借出超过该时长未归还，打印 Possible connection leak 告警（含借出线程与调用栈），不会强制销毁。0 或负值 = 禁用。
slowOperationThreshold3s操作耗时超过该值记录慢操作事件。非正值回落默认。
shutdownTimeout10sclose() 时等待在途操作归还连接的宽限期。0 = 不等待。
lifecycleCOMMONSCOMMONS = 启用后台维护（空闲驱逐、寿命回收、周期校验、min-idle 回填）；SIMPLE = 仅启动时预热一次 min-idle，无后台维护。

校验成本提示：FTP 的 NOOP 就是一次网络往返。规格明确禁止「每次 borrow 都 NOOP」， 因此只有连接空闲超过 validationInterval 才在借出时主动校验；其余情况靠后台 testWhileIdle。

策略轴（engine / lifecycle / observability）

枚举取值说明
PoolEngineTypeFAST、COMMONS性能算法：CAS fast-path / ThreadLocal 候选 vs. Apache Commons Pool 生命周期对象池。
LifecycleTypeSIMPLE、COMMONS后台维护开关。对 Fast 引擎真实生效；Commons 引擎本身即 COMMONS 生命周期。
ObservabilityTypeNONE、BASIC、FULL过滤链深度：NONE 无过滤器；BASIC/FULL 经 SPI 查找名为 basic/full 的 provider。

Profile 预设

大多数场景直接用预设，无需逐轴配置。入口 io.ftppool.core.FtpPoolProfiles：

方法enginelifecycleobservability适用
hybrid() 默认FASTCOMMONSFULL生产推荐
fast()FASTSIMPLENONE极致低延迟，无后台维护
commons()COMMONSCOMMONSNONE以 Commons Pool 生命周期为先
monitor()FASTSIMPLEFULL只要监控，不要后台维护
 
FtpPool pool = FtpPoolProfiles.hybrid()
        .host("ftp.example.com")
        .username("user")
        .password(System.getenv("FTP_PASSWORD"))
        .build();

FtpPoolBuilder 完整示例

import io.ftppool.core.*;
import io.ftppool.api.FtpProtocol;

import java.time.Duration;

FtpPool pool = FtpPoolBuilder.builder()
        // ---- 连接 ----
        .host("ftp.example.com")
        .port(21)
        .username("user")
        .password(System.getenv("FTP_PASSWORD"))
        .protocol(FtpProtocol.FTP)
        .encoding("UTF-8")
        // .sslConnection(FtpSslConfig.secureDefaults())   // FTPS 时配置

        // ---- 池 ----
        .poolName("main")
        .minIdle(2)
        .maxSize(20)
        .connectionTimeout(Duration.ofSeconds(3))
        .socketTimeout(Duration.ofSeconds(30))
        .dataTimeout(Duration.ofSeconds(60))
        .idleTimeout(Duration.ofMinutes(5))
        .maxLifetime(Duration.ofMinutes(30))
        .validationInterval(Duration.ofSeconds(30))
        .maxCreateConcurrency(2)
        .leakDetectionThreshold(Duration.ofSeconds(30))
        .slowOperationThreshold(Duration.ofSeconds(3))
        .shutdownTimeout(Duration.ofSeconds(10))

        // ---- 策略轴 ----
        .engine(PoolEngineType.FAST)
        .lifecycle(LifecycleType.COMMONS)
        .observability(ObservabilityType.FULL)

        // ---- 扩展 ----
        // .addFilter(myFilter)
        // .autoRegisterMBeans(false)
        .build();

autoRegisterMBeans 默认为 true：build() 时经 ServiceLoader 自动注册 JMX。 Spring Boot 自己管理 JMX，会显式关闭它以免重复注册。

Spring Boot YAML 参考

spring:
  tidepool:
    ftp:
      enabled: true
      host: ftp.example.com
      port: 21
      username: user
      password: ${FTP_PASSWORD}      # 环境变量注入，绝不硬编码
      protocol: ftp                  # ftp | ftps-explicit | ftps-implicit
      encoding: UTF-8
      pool-name: default

      pool:
        mode: hybrid                 # fast | commons | monitor | hybrid
        engine:                      # 可选：逐轴覆盖，缺省用 mode 预设
        lifecycle:
        observability:
        min-idle: 2
        max-size: 20
        connection-timeout: 3s
        socket-timeout: 30s
        data-timeout: 60s
        idle-timeout: 5m
        max-lifetime: 30m
        validation-interval: 30s
        max-create-concurrency: 2
        leak-detection-threshold: 30s
        shutdown-timeout: 10s

      observability:
        enabled: true
        metrics: true
        jmx: true
        slow-operation-threshold: 3s

      ssl:                           # FTPS 时使用
        trust-all: false             # UNSAFE，仅开发/测试
        hostname-verification: true

Duration 采用 Spring Boot 宽松绑定（3s / 5m / 500ms …）。属性类为 io.ftppool.spring.boot.FtpPoolProperties（prefix spring.tidepool.ftp），详见 Spring Boot 集成。

调优速查

场景建议
borrow 频繁超时先看 stats().pending() 与 borrowTimeouts；增大 maxSize 或缩短单次操作耗时，再考虑放宽 connectionTimeout。
连接被服务器静默断开调小 maxLifetime（如 5m）与 idleTimeout，让连接在被防火墙切断前回收。
不想有后台线程用 fast() 或 lifecycle(SIMPLE)，并设 validationInterval(0)。
连接风暴 / 认证失败频发降低 maxCreateConcurrency（默认 2）并适当预热 minIdle。
疑似连接泄漏保持 leakDetectionThreshold 开启，日志会给出借出线程与调用栈。
慢操作影响业务调小 slowOperationThreshold，结合指标定位是哪类操作慢。
